# Root-changelog bullets from bump pass the repository's own format check - Plan

## Goal Capsule

- **Objective:** a release PR generated by `version-management bump` passes this repository's `check:ci`, so the version PR can get green CI on its own head.
- **Means:** `bump` writes each root-changelog bullet as a top-level Markdown list item (`- <summary>`), and a test runs the repository's real `dprint check`, with the repository's `dprint.json`, over the root changelog that the real bump wrote.
- **Product authority:** the repository's root. One pull request off `main`; root merges.
- **Open blockers:** none for this fix. The release PR cannot release until the root rules on the 11 lightweight `v0.0.0` tags (Scope Boundaries).

## Product Contract

### Summary

The version PR that the dogfood Release opens fails `check:ci` at its first step, `pnpm format:check`. dprint rejects the `CHANGELOG.md` that bump wrote, because every bullet under `## <version>` starts with two spaces. After this change bump writes `- <summary>`, which dprint accepts, and a regression test proves it with the repository's own dprint binary and config.

### Problem Frame

- **Defect.** `rootBulletsOf` in `packages/version-engine/src/bump-derive.ts` maps each intent with a non-`none` bump to `` `  - ${intent.summary}` ``. `writeSurfaces` (`bump.ts`) passes that text to `ChangelogStore.appendReleaseSummary`, which appends `## <version>`, a blank line and the text to the root changelog.
- **Observed.** The release branch's head, a commit by `github-actions[bot]` built on `632e895`, fails `./bin/dprint check` with exit 20 on `CHANGELOG.md`. The diff dprint prints removes the two leading spaces from every bullet. The CI run the release workflow dispatched on that head failed, as did the one on the previous head. Every release PR this repository generates fails the same way.
- **Why no test caught it.** The only test that sees the root changelog text (`version.integration.test.ts`, "Two intents collapse into one consolidated version") compares it with a copied expected string over the fake changelog store, `'# Changelog\n\n## 2.0.0\n\n  - ship a\n  - fix b\n'`. That string pinned the defect.

### Requirements

- **R1.** Every bullet that bump writes into the root changelog is a top-level list item: `- <summary>`, with no leading whitespace.
- **R2.** The root changelog that the real `bump` writes, both fresh and appended to an existing changelog, passes `bin/dprint check` run with the repository's `dprint.json`. The test judges it with that real check, never with a copied expected string.
- **R3.** Member changelogs, parked changelogs and the intent consumption are unchanged.

### Acceptance Examples

- **AE1 (regression, red then green).** A new integration feature in `apps/version-management/tests/` runs the real `bumpCell` over the real workspace stores in a temp tree with the `surfaces` strategy and `rootChangelog: CHANGELOG.md`. It then runs the repository's `bin/dprint check --config <repository>/dprint.json CHANGELOG.md` in that tree and expects exit 0. On `main` it fails, printing dprint's diff; with R1 it passes. Covers R1, R2.
- **AE2 (non-vacuous).** The same scenario asserts that the changelog holds the new `## <version>` section and each intent's summary, built from the fixture's own values. dprint exits 14 when it finds no file, so a missing changelog cannot pass. Covers R2.
- **AE3 (both shapes, real intents).** The feature runs two rows: no root changelog yet, and an existing changelog with an earlier `## <version>` section. Each row carries one intent with a summary longer than the 120-column line width and one intent whose body has two paragraphs, as this repository's own intents do. Covers R2.
- **AE4 (real tree).** The release branch's `CHANGELOG.md` fails `bin/dprint check`; the same content with R1 applied passes. Covers R1.

### Scope Boundaries

- **The 11 lightweight `v0.0.0` tags are out of scope.** Once the release PR consumes the last intents, `github-release-management plan` checks every member's current version against its tag. It refuses with `refused: tag-annotation-lightweight, tag: @systemfsoftware/changeset-engine@v0.0.0`; on today's `main` it exits 0 with `phase=version`. The adoption ledger cannot carry these tags. `github-release-management adopt` records registry bytes, and none of these versions was ever published, so it writes every `v0.0.0` tag as `unpublished`. `plan` then refuses `version-burned` for `adoption-adapter@0.0.0`, whose annotated tag passes today. Rewriting, deleting or annotating remote tags is a root decision and is not part of this pull request.
- No change to `plan`'s integrity rules, the ledger, `release.yml` or the release PR itself.
- No new CI gate. The test runs in the CI `check` lane's `turbo test`, after `format:check` has fetched dprint's plugins.

## Planning Contract

### Key Technical Decisions

- **KTD1. Fix the generator, not the PR.** The release PR is regenerated by the dogfood run on every push to `main`, so a hand-edit would be overwritten and the next one would fail again.
- **KTD2. The test lives in `apps/version-management/tests/`, not `packages/version-engine/tests/`.** The Sandbox lane runs `pnpm --filter "./packages/*" test` with no network. `dprint.json` loads its plugins from `https://plugins.dprint.dev/*.wasm`, and the flake's `dprint` package pins only the binary, so a dprint-spawning test in a package would fail there. The CI `check` lane runs every workspace's `test` through `turbo` after `pnpm format:check`, with the flake's dprint on `PATH` and the plugins already fetched. The app composes `version-engine` with the real workspace stores, as its `main.ts` does.
- **KTD3. The judge is `bin/dprint check`, the command behind `pnpm format:check`.** It is spawned with `--config <repository>/dprint.json` and the temp tree as its working directory, through `effect/unstable/process` (the house lint bans `node:` imports in tests).
- **KTD4. Delete the copied string.** The fake-store assertion at `version.integration.test.ts:148-150` is removed rather than re-pinned. The real-store test (AE1) supersedes it, and the scenario's other assertions are unchanged.
- **KTD5. Turbo cache inputs.** The app's `test` task gains `$TURBO_ROOT$/dprint.json` as an input, so a change to the formatter config re-runs the test instead of replaying a cached pass.
- **KTD6. Intent.** One `.changeset/` intent: `@systemfsoftware/version-engine: patch`.

### Test admission

Gate: `test-layer-selection`, default refuse.

- **AE1 to AE3: admitted.** They reproduce a regression that reached a generated release PR, and they assert the observable contract: the root changelog passes the repository's format check. They are integration tests through the published `bumpCell` with the real stores, in the composing app.
- **Spawn exception, recorded.** The skill fails an integration test that spawns a process. This one spawns exactly one: the judge. The contract is "passes the repository's `dprint check`", and the only faithful oracle is that binary with that config; an in-process formatter would be a second, differently versioned implementation. The repository's integration tests already spawn real `git` and a served `turbo` binary as oracles.
- **AE4: not committed.** It is a one-time local check.

### Assumptions challenged (destructive review)

1. _"dprint and its plugins are available where the test runs."_ True only in the CI `check` lane and on machines that have run `pnpm format:check`, which fetches the plugins. The Sandbox lane is offline and runs only `./packages/*`, and the E2E image runs no app tests. So the test must not live in `packages/` (KTD2).
2. _"A two-space bullet is the only defect."_ Intent bodies can span paragraphs and exceed 120 columns. The rows include both (AE3), so the check judges what bump writes for realistic intents, not one short line.
3. _"A passing check proves bump wrote the section."_ `dprint check` passes on a file that lacks the section. AE2 asserts the new section and each summary are present, and a missing file exits 14.
